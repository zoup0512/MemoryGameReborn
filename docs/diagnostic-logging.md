# 对局诊断日志与手动上传

## 用途与边界

诊断功能用于追溯回合切换、网络断线、页面退出与对局结算之间的关系，不改变游戏规则，也不是修复某一场对局的自动退出问题。新日志只能覆盖安装/部署此版本之后的行为，不能补回旧版本未记录的信息。

两端保留业务对局 ID（`matchId`）、回合号和游戏 ID，便于关联。服务端记录邀请码创建、成功加入后与对局 ID 的映射。不要把客户端报告当作服务端权威事实：客户端时钟、事件和可选关联 ID 都可能不准确。

## Android 使用

在 **“我的” → “上传诊断日志”** 手动操作。上传前准备固定快照，并显示记录时间范围、大小和上传目的地；只有确认后才发送。取消不会上传。

日志记录连接/重连、会话状态、回合开始/结束、游戏页面启动/返回、退出意图、对战页面关闭来源，以及异常类型和有界调用栈。不采集系统 Logcat、其他应用日志或完整网络请求/响应；不记录密码、邮箱、昵称、访问/刷新令牌、验证码、游客秘密或安装身份凭据。

日志位于应用私有目录，按大小轮转、保留最近 7 天。单次报告正文不超过 192 KiB UTF-8；轮转日志预算为 4 × 128 KiB，待重试快照至多一份。上传失败保留快照，重试使用相同上传 UUID；上传成功不清空上传期间产生的新日志。日志仍受时间和容量上限约束，不承诺永久保留。

上传使用 HTTPS，不改变在线连接、账号或对局。对于原默认服务器 `ws://124.220.35.87:8091/ws`，仅诊断上传使用已信任的同一云服务 HTTPS 地址 `https://www.razor123.site/api/v2`，并复用已有旧游客凭证；不为上传执行游客迁移。WSS 环境使用同源 HTTPS。其他明文地址不会被自动转换并发送凭证。没有可用身份时需先建立在线游客/账号身份。

上传成功返回报告编号，请在反馈问题时提供该编号、事发时间、双方手机版本，以及邀请码（若有）。

## 服务端日志

关键业务事件同时保留近期内存事件和 INFO 日志。普通生产部署继续能从 systemd journal 检索，并新增有界滚动文件：

- 文件默认 `./logs/memorygames-pk.log`，可通过 `PK_LOG_FILE` 指定。
- 单文件 10 MB、滚动保留 14 天、归档总量上限 200 MB。
- 工作目录必须可写；文件权限和日志目录由部署用户管理，不应公开到 Web 静态目录。
- 事件包含对局建立/游戏计划、回合开始、完成请求接受或拒绝、回合结束是否由截止时间触发、认输、断开/重连、结算触发与结果。
- WebSocket 记录连接关联标识、关闭码、主动替换原因及发送/传输异常类型，不输出完整帧或认证凭据。

示例（实际事件名以代码为准）：

```bash
journalctl -u memorygames-pk.service --since '2026-10-14 21:20:00' --no-pager | grep 'match=对局ID'
grep '对局ID' logs/memorygames-pk.log
```

邀请码查询先定位成功加入映射，再按对局 ID 查询完整链路。邀请码会重复使用，必须结合时间，不可只按四位码判断同一场对局。

## 客户端报告接口

```text
POST /api/v2/diagnostics/uploads
Authorization: Bearer <现有 v2 access token 或旧游客 token>
Content-Type: application/json
```

```json
{
  "schemaVersion": 1,
  "uploadId": "客户端生成并在重试中保留的 UUID",
  "appVersion": "版本名称/版本码",
  "buildTime": "构建时间",
  "startedAt": 1790000000000,
  "endedAt": 1790000060000,
  "content": "逐行 JSON 的诊断记录",
  "matchId": "可选的业务对局ID"
}
```

响应包含 `id`、`uploadId`、`receivedAt`、`bytes`。同一用户/上传 UUID 的相同内容重试返回同一报告；不同内容返回冲突。报告所属用户来自服务端认证，不信任请求中的用户 ID。

上传总 JSON 上限 256 KiB，日志正文另限 192 KiB。只允许未压缩 JSON；请求实际读取字节数也受限制。仅该上传路径有独立上限，普通账号接口仍为 16 KiB。服务端再次执行字段白名单/脱敏，不把上传正文写入业务日志。

报告持久化在数据库，默认保留 14 天，每小时及写入时清理过期记录。每用户最多每滚动分钟 2 份、每 UTC 日 10 份；全局默认最多 1000 份，可用 `pk.diagnostics.max-reports` 调整（范围 1～10000）。相同报告的幂等重试不重复占配额。报告编号不赋予公开访问权。

## 管理员查询

控制台“客户端诊断”提供报告查询和纯文本查看。接口仍需管理员 Token 或管理员浏览器会话：

```text
GET /api/admin/diagnostics?userId=<可选>&matchId=<可选>&limit=20
GET /api/admin/diagnostics/<报告编号>
```

列表只返回元数据，正文点击后读取，不能通过报告 ID 匿名下载。正文使用纯文本展示，上传内容不能作为 HTML 或脚本执行。

排查时先按报告编号/用户/对局查询客户端记录，再结合服务器对应时段日志。确认页面退出之前收到的事件、回合/gameId、关闭来源及断线顺序，而不是把大厅标题视为服务器判定退出。

## 构建、验证与上线

服务端使用 JDK 17 执行 `./gradlew test bootJar`；管理网页脚本测试使用 `node --test src/test/js/admin-console.test.cjs`。Android 使用 JDK 17 执行 `./gradlew assembleDebug`，日志纯 Java 测试脚本为 `tools/test-diagnostics.sh`。

新增 Flyway V7 诊断报告表；升级前备份数据库和旧 JAR，确认现有 schema 版本后进行增量迁移。普通测试 profile 的 Hibernate create-drop 不能替代真实 Flyway 迁移验证。PostgreSQL 验证依赖 Docker，应单独记录是否执行。

生产反代必须同时放行 `/api/v2/diagnostics/uploads` 和受管理员认证保护的 `/api/admin/diagnostics`。现有云部署的 `/api/v2/`、`/api/admin/` 前缀代理覆盖这些路径，但仍需部署新服务端 JAR。HTTPS 终结后保持可信 TLS 转发配置，不能用生产允许 HTTP 开关代替 HTTPS。

本地代码实现和构建并不等于上线。上线需更新服务端并安装新 APK 后才能开始采集，旧客户端不会自动获得日志上传功能。
