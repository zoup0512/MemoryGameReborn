# 游客与注册账号体系

## 目标与边界

游客和注册用户使用同一个永久 `pk_user.id`。新游客通过设备秘密创建/恢复身份；游客绑定已验证邮箱时原地升级，不创建第二个玩家，不复制战绩，不重复发放欢迎礼。登录已有账号是账号切换，不自动合并两个账号的金币、ELO、赛季奖励或在线历史。

单机游戏继续离线可用，现有 ActiveAndroid 数据库不参与认证，不因登录、退出或服务端故障而清除。单机货币和在线货币明确隔离：在线余额来自服务端，单机 `LocalUser.money` 不上传，不用在线结算增减它。

生产账号网络必须 HTTPS/WSS。当前公网 `ws://124.220.35.87:8091/ws` 是旧游客兼容地址，不是新账号接口的安全部署地址。不能把 `ws://` 字符串改成 `wss://` 就当作已启用 TLS。服务端默认拒绝所有明文账号请求（包括 loopback）；只有隔离测试显式开启 `pk.auth.allow-http=true`。

## 核心不变量

1. 游客升级前后 `userId`、金币流水、ELO、战绩、风控状态不变。
2. UUID/installationId 是定位字段，不是恢复凭证。
3. 服务端只保存凭证哈希，密码使用 BCrypt；客户端凭证使用 Android Keystore 保护。
4. 已迁移用户不再通过旧 UUID 无凭证恢复。迁移必须证明持有有效旧 token。
5. 账号切换不合并在线资产；排队、好友房等待、练习启动与对局中不允许切换身份。
6. 同一用户只有一个在线 PK 控制连接。旧连接被替换时必须收到明确通知并关闭。
7. token 失效、被撤销、正式账号登录失败均不能静默创建游客覆盖原身份。
8. 新用户欢迎礼只来自服务端事务和金币流水，不接受客户端余额。
9. 排行榜判断本人使用 `userId`，不是昵称。
10. 账号删除保留必要的对局审计，但匿名化个人身份，删除用户不进入排行榜。

## 身份、设备和会话

用户主表保留现有在线经济和统计字段，增加游客/正式账号类型、头像、升级时间和删除生命周期字段。身份、设备、会话、验证码与账号事件分别持久化，避免继续用 `pk_user.token` 承担所有认证职责。当前第一期 `pk_identity` 是每用户一行，将游客安装凭证与邮箱绑定放在同一行；注册后清除游客秘密。它不是已完成的多提供者身份模型，未来 OAuth 需追加独立提供者身份表及唯一约束，而不是直接往当前邮箱列塞第三方标识。

- 游客设备身份：客户端生成 installationId 和 256 位随机 guestSecret；服务端验证 guestSecret 哈希。卸载/清数据/丢失 Keystore 后，游客不能保证恢复，界面必须提前说明。
- 邮箱身份：邮箱验证成功后绑定，邮箱标准化、唯一，密码只保存 BCrypt 哈希。
- Access token：随机不透明短期 token，默认 15 分钟，数据库保存哈希。
- Refresh token：默认 30 天，每次刷新轮换；旧 token 重放撤销对应会话，不能因为异常事务回滚而撤销失败。
- 设备：每台设备独立会话，支持当前设备退出、全设备退出、设备列表与单设备撤销。设备数量有上限。
- PK 连接：短期 access token 建立实时连接后，会话撤销仍需立即生效；不能让旧连接继续操作对局。

## 用户操作

### 首次游客

没有网络时继续单机。有安全账号服务时静默创建游客；原有安装先尝试旧 token 迁移，成功后才废弃旧凭证。未配置安全服务时旧游客功能保留，但不能通过明文发送邮箱、密码、验证码或新会话凭证。

### 游客绑定邮箱

1. 保持当前游客身份。
2. 输入邮箱，发送验证邮件。
3. 输入验证码和密码。
4. 服务端验证邮箱、验证码、唯一性及账号状态，在事务内原地升级。
5. 轮换会话，重连 PK，继续使用原 userId。

### 登录已有账号

明确提示在线金币/ELO不合并；登录成功后切换服务端身份，并清除上一账号的在线缓存和活动快照。本机单机数据原样保留，不能在个人中心将它误称为已同步云端。

### 退出

服务端先撤销会话，再清除本机账号会话。不能因为服务端临时失败就假装所有设备已退出。新游客身份与正式账号分离；不能再次用已升级游客的设备秘密恢复正式账号。

### 找回密码

发送接口不泄漏邮箱是否存在；验证码限时、单次使用、有尝试次数上限。密码重置后撤销全部旧会话。没有邮件服务配置时明确失败，禁止把验证码返回 API 或记录日志作为生产替代方案。

### 注销

正式账号要求重新验证密码。申请后立即撤销会话并进入 7 天冷静期，期间可用邮箱和密码取消申请。到期后匿名化个人信息，保留必要审计与对局记录。禁止注销作为逃避风险状态或无限领取欢迎礼的方式。

## REST 接口契约

基础路径 `/api/v2`，认证请求使用 `Authorization: Bearer <accessToken>`。

认证响应：

```json
{
  "accessToken": "opaque-secret",
  "refreshToken": "opaque-secret",
  "accessExpiresAt": 0,
  "refreshExpiresAt": 0,
  "sessionId": "session-id",
  "user": {
    "userId": 10001,
    "accountType": "GUEST",
    "nickname": "薄荷小狐",
    "avatarValue": "avatar_1",
    "nextNicknameChangeAt": 0,
    "elo": 1000,
    "balance": 60,
    "wins": 0,
    "losses": 0,
    "draws": 0,
    "email": null,
    "emailVerified": false
  }
}
```

| 方法和路径 | 用途 |
|---|---|
| `POST /auth/guest` | 创建或凭设备秘密恢复游客 |
| `POST /auth/migrate` | 使用旧 token 保留原 userId 迁移 |
| `POST /account/email-verification` | 为当前游客发送邮箱绑定验证码 |
| `POST /auth/register` | 验证后原地升级游客 |
| `POST /auth/login` | 登录已有邮箱账号 |
| `POST /auth/refresh` | 轮换短期和长期凭证 |
| `POST /auth/logout` | 撤销当前会话 |
| `POST /auth/logout-all` | 撤销全部会话 |
| `POST /auth/password-reset/request` | 请求密码重置验证码 |
| `POST /auth/password-reset/confirm` | 验证并重置密码 |
| `GET /me` | 当前用户资料（直接返回 user 对象） |
| `PATCH /me/profile` | 更新昵称与内置头像 |
| `GET /me/devices` | 当前账号设备列表 |
| `DELETE /me/devices/{deviceId}` | 撤销指定设备会话 |
| `POST /me/delete-request` | 申请账号删除 |
| `POST /auth/delete-cancel` | 验证身份并取消待删除申请 |

错误统一为 `{ "code": "MACHINE_READABLE_CODE", "message": "用户可读说明" }`，配合 HTTP 400/401/403/409/422/429/503。不要在认证响应、日志或异常中输出密码、验证码和完整 token。

### 个人资料与昵称审核

- 头像只接受 `avatar_1`～`avatar_12`，客户端展示内置头像网格，不支持 URL、相册或上传。
- 新游客不传 `nickname`（或传 `null`）时由服务端受控词库生成默认昵称。显式传入的昵称，包括客户端随机生成的昵称，不能被当成可信默认值而跳过审核。已有游客恢复和旧 WS 重新注册不覆盖原昵称。
- 自定义昵称去除首尾空白后须为 2～16 个 Unicode 码点，禁止控制字符、格式字符和未分配字符；通过服务端本地规则与外部文本机审后才能落库、公开显示。
- 默认未配置机审时，自定义改名返回 `503 NICKNAME_MODERATION_UNAVAILABLE`，不是放行。新游客安全默认昵称与单独更换头像不依赖外部机审。
- 审核拒绝或需复核时不公开新昵称；客户端保留草稿，分别提示不符合规范、暂无法使用或服务暂不可用，不显示命中词、风险分数等内部信息。
- 同时修改昵称与头像时整体成功或整体失败，审核失败不部分保存头像、不更新改名冷却。首次改名立即生效，之后每 7 天一次；`nextNicknameChangeAt` 为 epoch 毫秒，`0` 表示从未改名，过去时间表示已可再次修改。
- “我的”和账号中心共用当前账号资料。离线本机默认资料不等于云端账号；未审核昵称草稿不能作为在线昵称发送或展示，登录既有账号不能自动用本机草稿覆盖其资料。
- 存量昵称不因客户端升级自动覆盖。历史昵称复核、安全替名与外部审核配置见 [昵称机器审核](nickname-moderation.md)。

## 数据迁移与兼容

- 追加 Flyway V4（账号、身份和会话）及 V5（昵称修改冷却），不能重写已有 V1～V3。昵称首次修改立即生效，之后每 7 天一次；同名更换头像不触发冷却。
- 旧用户默认是游客，保留现有主键、经济和统计。
- 旧 WS `register/auth` 仅对尚未迁移的游客保留兼容。
- 迁移证明是有效旧 token，不能通过 UUID 猜测原账号。
- 新 WebSocket `auth` 使用 access token；`auth_ok` 增加 accountType/avatarValue，并返回当前有效认证 token 而不是遗留 token。
- `TopEntry` 增加 userId，历史增加 matchId/opponentUserId，旧客户端可忽略新增字段。
- Android 账号凭证不加到现有 ActiveAndroid 表，避免破坏旧单机数据库。
- 身份存储必须区分账号服务来源，不能在调试切换服务器后把原服务器 token 发送给另一个来源。

## 不自动迁移的数据

- 单机金币不导入在线钱包。
- 本地关卡不作为在线竞技计分依据。
- 两个在线账号的 ELO、金币和战绩不合并。
- 手机备份不作为游客账号恢复机制。

## 后续独立扩展

以下需要独立业务规则与部署配置，不能以占位接口声称已经可用：第三方 OAuth 登录（提供者客户端 ID/回调域名）、跨设备单机进度云同步、持久好友关系、高价值赛季奖励、完整跨设备对局接管、实时状态多实例共享。第一期保留同用户单 PK 控制权，不引入 Redis 或重写现有权威结算。

## 部署与验收

参见 [账号服务部署与验收](account-system-deployment.md)。必须先部署并验证 TLS、邮件投递及数据库增量迁移，再将新账号客户端指向该地址。不得在旧明文生产地址直接启用密码登录。
