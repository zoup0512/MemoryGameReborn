# Harmony 手机 App：对齐 Android 单机金币与解锁

## 已确认的范围

- 对齐 Android **正式版单机 Sprint** 的金币获取、初始开放项、永久解锁价格及购买界面。
- 保留 Harmony 当前免费重新开始、无限暂停及现有失败流程；不增加金币续关。
- 不接入在线钱包、账号、充值、广告、签到、VIP 或全解锁商品；Debug 也不自动全解锁，便于验证真实规则。
- 不考虑 Harmony 旧存档兼容，不追补历史金币、不做旧用户权益迁移。使用新的存档版本/命名空间，旧文件不主动删除，也不导入。
- 金字塔初始锁定，点击确认后以 **0 金币**永久解锁。
- 不修改 Android 或服务端代码，不自动提交或推送。

## 一、静态规则与金币计算

新增独立、可单测的经济规则模块，明确使用 Harmony 的稳定游戏 ID（Android 原 ID + 1），不以首页数组下标识别游戏。

首次建立经济存档赠送 **60 金币**，初始化后立即持久化；重启不重复赠送。

### 默认开放与解锁价格

默认开放 13 款：记忆网格、旋转网格、六边形、谁是新来的、数一数、跟随路径、图像漩涡、正确吗、全部相同、纸飞机、和之前一样吗、颜色、对称。

| 游戏 | 解锁价格 |
| --- | --- |
| 抓住它们 | 150 |
| 找到图片、激光、舒尔特方格 | 各 300 |
| 独一无二 | 400 |
| 多与少 | 500 |
| 数字排序、找出全部 | 各 600 |
| 248 | 1000 |
| 金字塔 | 0，仍需确认解锁 |

单独保存“是否需要解锁”，不能用价格为 0 推断默认开放。

### 获取规则

奖励在实际成功事件发生时入账，不等待整局结算。失败、暂停、返回列表、重开、保存历史或恢复后台检查点不额外发奖。

- 通常游戏按成功时的当前关卡 L 发放：L≤3 为 0；4–10 为 1；11–14 为 2；15 及以上为 3。
- 谁是新来的、纸飞机、和之前一样吗、颜色：L≤3 为 0，之后每次成功为 1。
- 舒尔特：成功找到数字时，以该次成功对应的进度编号计算，每逢 3 的倍数发 1；在递增编号前计算，避免偏移，找到 48 时仍正确结算。
- 248：按累计分数金币函数的差值发放。累计奖励在 1024/1536/2048/2560/3072 分分别为 1/3/6/10/15，此后每增加 512 分多 5；一次跨多个阈值完整补齐，零得分、拖动取消及重复反馈不重复发奖。
- 同一游戏可重复游玩赚币，不添加 Android 未有的每日上限或首次通关限制。

## 二、本地存储与一致性

修改 `services/ProgressStore.ets`：

- 在新存档结构中增加整数金币余额和永久解锁游戏 ID 集合，保留成绩、教程、音效偏好和后台检查点机制。
- 提供查询余额、查询权限、奖励入账和购买解锁接口；页面不直接改余额。
- 购买前在 Store 层再次校验游戏、余额和已购状态；余额扣除与解锁状态在同一份持久化快照中更新。
- 购买串行化，连点和重复购买不会重复扣款；保存成功后才关闭购买弹窗并展示已解锁，失败则提示并允许重试，不伪报成功。
- 金币写入与既有成绩写入共用有序队列，避免旧快照覆盖新余额；明确写入失败状态，防止读取失败后悄悄重置钱包。
- 后台检查点恢复只补记历史，不重新发放已经在成功事件入账的金币。

## 三、首页与解锁交互

修改 `components/AndroidScreens.ets` 和 `pages/Index.ets`，复用现有白卡弹窗与 Android 资源，不重设计游戏列表。

- 首页顶部展示本地金币余额及原版金币图标，不保留无效的充值入口或“获取更多金币”气泡。
- 未解锁游戏显示 Android 风格深灰遮罩、白色锁及价格；已解锁项继续展示最高关卡。金字塔保留 Android 秘密游戏的锁态展示，弹窗价格为 0。
- 点击锁定项显示：游戏名、解锁价格、当前余额、“解锁 · N 金币”和“取消”。
- 余额不足时显示还差多少金币及游玩已解锁游戏赚币的说明，禁用确认按钮。
- 解锁成功后关闭弹窗、刷新余额与锁态，**留在列表**；用户再次点击后按已有教程状态进入。
- 取消及系统返回仅关闭弹窗，不扣款、不启动游戏。
- 首页、教程开始、重玩和结算推荐统一校验权限，避免通过推荐或直接调用 `start()` 绕过锁。
- 使用明确的响应式余额和解锁快照刷新界面；不依赖普通 Store 对象内部变化触发刷新。
- 不新增 Android 离线结算页当前没有的金币奖励明细，不改变现有游戏操作和计时。
